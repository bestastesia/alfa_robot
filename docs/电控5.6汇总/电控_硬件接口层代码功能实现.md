# 电控 - 硬件接口层代码功能实现

**完成日期：** 2026/05/01

## 核心成果

基于 ros2_control 框架实现了 `AlfaRobotHW` 硬件接口层，采用 Driver-Joint 分层架构统一管理 15 个关节。Driver 层按总线组织（5 个 Driver 覆盖 can0~can4），Joint 层通过 `IJoint` 抽象接口统一导出 position command/state，控制器无需关心底层协议差异。can0 上 ZeroErr/RMD/Cylinder 三种协议顺序读写，避免总线冲突。

急停采用双通道设计：

- CAN 硬件急停：监听 ID=0x7FF 帧，响应 < 50ms
- ROS 话题急停：`/emergency_stop_trigger`，灵活远程触发

触发后遍历所有关节执行对应制动动作（ZeroErr stopMotor / RMD 抱闸 / CANopen QuickStop / Cylinder 闭阀），并阻断后续所有写操作。安全关机时可选自动归位到预设安全位置（30s 超时保护）。位置误差监控采用动态/静态双阈值，超限持续超过容忍时间后升级报警。

**代码位置：** [alfa_robot_hardware.hpp](../../src/alfa_robot_hardware/include/alfa_robot_hardware/alfa_robot_hardware.hpp) / [alfa_robot_hardware.cpp](../../src/alfa_robot_hardware/src/alfa_robot_hardware.cpp) / [i_joint.hpp](../../src/alfa_robot_hardware/include/alfa_robot_hardware/joint/i_joint.hpp)

## 当前效果

作为 ros2_control 插件正常加载，15 个关节接口完整可用。can0 三种协议共存读写无冲突。急停从触发到电机停止 < 50ms，解除后可恢复。位置误差超阈值时产生 WARNING/ERROR 日志。

## 测试方法

- `ros2 control list_hardware_interfaces`，确认 15 个关节接口存在
- `ros2 topic echo /joint_states`，确认位置值正常
- `cansend can0 7FF#01` 触发急停验证电机停止，`7FF#00` 验证恢复
- 同时移动不同协议关节（leftjoint2[ZeroErr] + leftjoint5[RMD]），验证协调正常

## 存在问题与后续方向

关节参数（Node ID、限位、方向等）硬编码在 `buildJoints()` 中，修改需重新编译，后续需移至配置文件。位置误差仅产生日志报警，不触发主动安全动作，后续需增加超限时自动急停/降速。内部诊断信息未通过 ROS 话题发布，外部无法监测，后续需发布 `/hardware_diagnostics` 诊断话题。
