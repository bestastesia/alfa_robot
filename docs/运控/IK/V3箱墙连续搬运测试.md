## Rerun逐箱增量时间轴（2026-09-14）

每个搬运轮次的完整规划与碰撞检查完成后（双臂对称双箱、中心单箱，或降级后的单箱；均含吸附、撤离、身后放置、释放消失），立即一次性发布该段轨迹，后台继续下一轮。正吸失败后还在尝试顶吸时不发布候选失败；只有最终选定的成功结果或最终失败诊断才成为一段。**不等整墙规划结束，不等UI播放，不逐帧发送ROS消息。**

Rerun复用每1024帧的机器人变换批量写入，箱体的每一帧姿态、吸附与消失状态全部保留，没有删帧、播放等待或碰撞精度调整。整项任务共用连续的 `task_frame`：新箱轨迹追加到末尾，场景快照在对应轨迹帧生效，不在收到后台规划结果时提前移除箱子。RViz仍使用原整段完成后的20Hz回放，规划顺序与前后箱末态衔接不变。

### 消息与补齐

- `/<启动节点名>/task_json_segments`（本序列入口默认 `/v3_box_wall_grasp_demo/task_json_segments`）：reliable / transient-local / depth **32**，本demo为15个正常轮次；发生单臂降级时最多25个分段，不依赖depth 1保留分段历史。
- 原 `/<启动节点名>/task_json`（本序列入口默认 `/v3_box_wall_grasp_demo/task_json`）：reliable / transient-local / depth **1**，保留最终完整结果，作为晚启动/重连的补齐来源；发布节点必须仍存活且尚未用后续任务覆盖该快照，非跨进程持久化存储。
- 用 `publisher_id`、`task_id`、`segment_index`、半开帧范围 `[frame_begin, frame_end)` 校验身份、重复、重叠和缺段；乱序先缓存，只写连续前缀。最终结果核对已写帧与场景，只补缺失后缀，不重复成功前缀。不同话题不假设到达顺序。
- 失败段保留真实连续诊断与准确失败末帧，失败箱不移除。后续同任务完整快照不会再写一遍此前成功箱子。

## 搬运规则

- 固定顺序：`20–24 → 15–19 → 10–14 → 5–9 → 0–4`，即从上到下，同排按ID递增。
- 非底排先正吸，完整搬运解算失败后顶吸。`arm=auto` 的顺序为正吸左、正吸右、顶吸左、顶吸右；指定手臂时只在该臂尝试两种方式。
- 底排 `0–4` 只顶吸。判定依据为箱底与墙底的高度，不把“剩余箱中的最低一排”重新当作底排。
- 顶吸在顶面中心上方预接触，向下接近，吸附后朝机器人方向抽离；正吸保留原路径。
- 完整周期：升降选高 → 预接触 → 接触/吸附 → 携箱抽离 → 后方搬运 → 释放消失 → 空载回home → 升降归零。
- 箱体在后放姿态仍可见、附着并参与碰撞；到 `release_box` 帧才解除附着并消失，无下落或落地仿真。剩余箱、机器人和环境持续参与规划碰撞检测。
- 只有完整周期（包括空载复位）成功才提交状态。失败尝试不执行、不删除箱体；两种吸附方式均失败时停止，不跳箱。
