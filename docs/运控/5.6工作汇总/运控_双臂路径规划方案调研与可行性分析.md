# 运控 - 双臂路径规划方案调研与可行性分析

**完成日期：** 2026/05/06

## 核心成果

对主流运动学求解器在双臂协调规划场景下进行了对比调研和实机验证，明确了各求解器的能力边界和适用场景：

- **BioIK**：基于进化算法，原生支持树结构的多末端执行器 IK 求解，是当前唯一可用于 `dual_arm_with_base`（双臂+升降+转盘整体规划组）的求解器。缺点是求解耗时较长（2~5s），且参数（搜索分辨率、迭代次数、种群规模）对求解质量和速度影响敏感。
- **pick_ik**：基于采样+梯度下降，单臂链式结构下求解速度最快，适合 `left_arm` / `right_arm` 单独规划。但不支持树结构，无法处理多末端执行器，误用于双臂组会导致交互式标记消失。
- **TrackIK**：基于数值迭代，收敛快但依赖初始值质量，容易陷入局部最优。对双臂协调场景的鲁棒性不足。
- **KDL**：ROS 官方默认求解器，基于数值雅可比迭代。不支持树结构，且对奇异点附近和远距离初始值表现不稳定，双臂场景基本不可用。

**结论：** 双臂整体规划必须使用 BioIK，单臂独立规划优先使用 pick_ik。当前项目采用混合策略——双臂组用 BioIK，单臂组用 pick_ik，兼顾能力与效率。

**代码位置：** [kinematics.yaml](../../src/alfa_robot_moveit_config/config/kinematics.yaml)

## 验证方法

- 将 `dual_arm_with_base` 求解器分别设为 BioIK / pick_ik / KDL，观察 RViz 交互式标记是否显示
- 分别用三种求解器拖动末端执行器，记录规划成功率和耗时
- 单臂组切换 pick_ik 与 BioIK，对比求解速度

## 存在问题与后续方向

当前双臂规划完全依赖 BioIK 同步求解，即左右臂必须同时规划出解才算成功。这种方式虽然能保证双臂协调性，但求解慢且不够灵活。实际产线中很多场景并不需要严格的同步规划——例如抓取-放置任务中，左右臂可以在时间上有先后。后续需要研究更灵活的双臂规划策略，包括异步到位、串行规划、升降协调等，详见下一份报告。
