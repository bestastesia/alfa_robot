# Linear 项目推进规范

目标：让工程师不用每次等用户提醒，也能把 Linear、Git、验收证据写得短、准、可追溯。

## 1. 总原则

- Linear 不是写论文的地方，优先高信息密度。
- 一个 issue 只对创建时的验收目标负责，不无限背后续所有想法。
- 描述写“要做什么”，评论写“推进到哪”，Done 评论写“证据在哪”。
- 能用链接和证据说明的，不要长篇复述。

## 2. Issue 描述怎么写

建议只保留 5 项：

```md
# 目标
一句话说明要解决什么。

# 范围
本 issue 做什么，不做什么。

# 验收
完成后怎么判断通过。

# 依赖
依赖哪个 issue、分支、文件、实物或外部输入。

# 产物
预计输出代码、文档、截图、视频、日志、CSV、模型或实物结果。
```

不要写大段背景。背景如果很长，放 Project Document 或 Notion。

## 3. 评论怎么写

普通推进评论控制在 3～6 行：

```md
进展：完成 A/B，发现 C。
证据：链接/路径/截图/commit。
风险：目前卡在 D。
下一步：做 E，预计 F 前完成。
```

不要把完整调试过程、所有猜想、所有终端输出都贴进去。只贴结论和关键证据。

## 4. Done 前必须留验收评论

Done 评论模板：

```md
验收结论：通过 / 暂不通过 / 部分通过。
完成内容：A/B/C。
证据：commit、分支、图片、视频、日志、数据路径。
验证：运行了什么，结果是什么。
遗留：不阻塞本 issue 的后续方向。
后续 issue：如有，贴链接；没有就写无。
```

没有验收评论，不建议把 issue 直接 Done。

## 5. 后续测试和新想法怎么处理

- 原验收已达成：原 issue 可以 Done。
- 必要验证：新建 `验证 / xxx` issue。
- 探索优化：放 Backlog。
- 只是想法：写在 Done 评论的“遗留/后续方向”。

不要因为“以后还可以测更多”让 issue 永远开着。

## 6. Project / Milestone / Issue 拆分

- Project：一个较大方向，例如 v5 运控全流程。
- Milestone：一个阶段，例如可视化仿真、动力学仿真、sim-to-real。
- Issue：一个负责人能闭环的具体任务。
- Sub-issue：某个 issue 里拆出的独立阻塞点。

如果任务能被独立验收、独立负责人推进、会阻塞主线，就拆 sub-issue。

## 7. 阻塞和延期

Blocked 不是状态摆设，必须说明：

```md
阻塞原因：
等待谁：
需要什么输入：
影响哪个 Milestone：
解除后下一步：
```

延期时不要只改日期，要评论说明原计划、实际进度、延期原因、新截止时间。

## 8. Git 关联规则

只有提交内容直接对应某个 Linear issue 的验收目标、修复项或推进内容时，commit 才必须带魔法词和 issue ID。

默认格式：

```text
Refs TIM-xx: 中文说明
```

只有确认提交合并后应关闭 issue，才用：

```text
Fixes TIM-xx: 中文说明
Closes TIM-xx: 中文说明
Resolves TIM-xx: 中文说明
```

不要只写：

```text
TIM-xx: 中文说明
```

这个不够稳定，Linear 可能不识别为关联。

如果这次提交只是当前分支的常规维护、协作区整理、架构清理、通用重构，且不直接对应任何 Linear issue，不要强行写 `Refs/Fixes/Closes/Resolves`；使用普通中文提交标题即可，避免把无关提交挂到 issue 上。

## 9. 分支规则

分支名包含 issue ID，描述用短英文：

```text
tim-41-mujoco-planning-scene
```

不要使用很长的中文自动分支名，避免终端、脚本和 CI 兼容问题。

## 10. 评论 resolve 规则

可以 resolve：问题已回答、误会已澄清、已拆新 issue、已有明确结论。

不要 resolve：还在等确认、包含关键证据、老板还没验收、里面有未处理风险。

resolve 表示讨论闭环，不是把不想看的内容隐藏。

## 11. 非代码任务也要留证据

机械安装、采购、测试、会议、线下调试也可以进 Linear。

证据可以是：照片、视频、会议纪要、采购单、测试记录、负责人确认、实物状态说明。

不要因为不是代码就只留在聊天里。

## 12. 给 AI 工程师的最低要求

开工前：读 issue 描述、最新评论、关联 issue、关联 commit。

收工时：留短评论，说明完成内容、证据、验证、遗留、下一步。

如果同时有 `.ai_teamwork`：Linear 是正式进度，本地 md 是 AI 协作上下文，两边不要互相替代。
