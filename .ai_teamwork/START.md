# AI 协作快速入口

这是 AI 团队的轻量协作区。目标不是建立复杂制度，而是让每个新开的 Codex / ClaudeCode 窗口用最少上下文快速知道：项目现在做到哪、其他 AI 怎么理解、自己接下来该干什么。

## 开工只读这 3 个文件

1. `.ai_teamwork/NOW.md`：项目当前状态、近期重点、重要背景。
2. `.ai_teamwork/TASKS.md`：当前任务和负责人。
3. `.ai_teamwork/LOG.md`：当前主线/当前分支的推进交接，只记录会影响后续工程师接手的信息。

如果任务明确要求某个岗位，再按需读 `.ai_teamwork/ROLES.md` 和 `.ai_teamwork/engineers/` 下对应工程师长期注意事项。

如果任务来自 Linear、需要更新 Linear、或需要提交 Git，先读 `.ai_teamwork/LINEAR_WORKFLOW.md`，不要在 issue 里长篇大论。

## 工作方式

- 用户主导方向，AI 负责高效执行和补充信息。
- 不追求全自动管理，不搞复杂审批。
- 开始前快速确认任务；结束后判断是否需要写 `.ai_teamwork/LOG.md`：只有影响当前主线/当前分支推进、需要后续工程师知道的内容才写。
- 如果发现会和其他 AI 改同一块文件，先提醒用户或项目经理。
- 如果没有明确任务，就先读 `TASKS.md`，不要自己发散改代码。


## LOG 写入边界

`.ai_teamwork/LOG.md` 不是所有 AI 操作流水账，只是主线交接日志。

应该写入：

- 当前分支/当前主线推进产生了可复用结论。
- 改了关键代码、文档、任务状态或 Linear 主线归属。
- 有 blocker、依赖、风险、验收证据需要后续工程师接住。
- Linear 操作直接改变项目推进，例如迁移 issue、调整 milestone、关闭/荣退 Project。

不应该写入：

- 普通问答、一次性查询、临时分析。
- 单纯处理 Linear 使用方法、界面设置、通知、演示管理等不影响工程推进的操作。
- 没有持久结果、不会影响下一个工程师开工判断的操作。

如确实想留操作痕迹但不影响工程进度，可写入本地忽略文件 `.ai_teamwork/OPS_LOG.local.md`。

## 收工交接格式

在 `.ai_teamwork/LOG.md` 追加：

```md
## YYYY-MM-DD 角色 / AI / 任务
- 做了什么：
- 改了哪里：
- 验证结果：
- 留给下个 AI：
```

## 归档阅读规则

`.ai_teamwork/archive/` 只用于历史追溯。默认开工不要阅读归档内容，除非用户或项目经理明确要求查旧任务。
